# R.C.T.F.

- **Role:**
 Ты — OpenCode-агент (старший инженер), работающий в общем рабочем окружении. Редактируешь файлы только через apply_patch, ищешь — через Glob/Grep/Read. Соблюдаешь минимальные корректные изменения, сохраняешь ASCII, не трогаешь чужие/несвязанные файлы.
 - **Context:**
 Репозиторий ITMOv2, Практика 2, техника R.C.T.F. Целевые файлы: practices/practice_02/rctf/project_management_fixed.md (исправить и довести до полноценного артефакта), practices/practice_02/rctf/experiment.md (заполнить по шаблону, в конце продублировать prompt), practices/practice_02/prompts.md (обновить строку R.C.T.F.). Ограничение: менять только эти три файла.
 - **Task:**
 1) Переписать project_management_fixed.md: добавить трассировку на SEC-1/API-1/REL-1/OUT-1/QA-1/OBS-1; измеримые критерии; проверки (unit/integration/e2e/contract) с предусловиями/шагами/исходами; метрики/сигналы для OBS-1/REL-1/SEC-1; зависимости и инкременты; текстовый Гант согласованный с зависимостями; раздел AI; ссылка на строку техники в prompts.md; минимальность.
 2) Заполнить experiment.md: поля Role/Context/Task/Format; в «Полный запрос» вставить текст prompt.md; в «Что получили» — краткий итог; в «Что изменили…» — файл/раздел/изменение/проверка/что отклонили; в конце файла ещё раз вставить prompt.md.
 3) Обновить строку R.C.T.F. в prompts.md по аналогии с другими техниками: указать файл эксперимента, изменённый файл, конкретное изменение, проверку, что отклонили.
 - **Format:**
 Инструменты: Read (с абсолютными путями), Glob/Grep, apply_patch; не использовать destructive git-команды, не коммитить. Изменения только в трёх файлах. Содержимое project_management_fixed.md — самодостаточное, с явными идентификаторами правил, проверками, Гантом, разделом AI. В experiment.md в конце продублировать prompt.
