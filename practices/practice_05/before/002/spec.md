# Feature Specification: Сортировка задач в GUI TaskHub

**Feature Branch**: `002-tasks-sort-gui`

**Created**: 2026-11-01

**Status**: Draft

**Input**: Пользователь хочет добавить возможность сортировать задачи по клику на заголовках колонок в Tkinter/ttk интерфейсе TaskHub. Заголовки колонок должны быть кликабельными, с визуальным индикатором направления сортировки (▲/▼), циклическим переключением asc → desc → без сортировки и интеграцией с backend через controller.list_tasks.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Сортировка задач кликом по заголовку колонки с визуальным индикатором (Priority: P1)

Пользователь видит таблицу задач с колонками "Название", "Статус", "Срок", "Теги". Заголовки колонок кликабельны (курсор меняется на руку при наведении). Пользователь кликает на заголовке — задачи перестраиваются по выбранному полю. Повторный клик на ту же колонку переключает направление сортировки циклически (возрастание → убывание → без сортировки). Клик на другую колонку сбрасывает индикатор на предыдущей колонке и устанавливает новый на выбранной. В заголовке активной колонки отображается текстовая стрелка ▲ (по возрастанию) или ▼ (по убыванию).

**Why this priority**: Основная ценность фичи — возможность отсортировать задачи визуальным действием без необходимости знать параметры API.

**Independent Test**: Открыть GUI, кликнуть на заголовке "Название", проверить что задачи перестроились по алфавиту и появилась стрелка ▲. Кликнуть снова — проверить переключение на ▼. Кликнуть на другую колонку — проверить перемещение индикатора.

**Acceptance Scenarios**:

1. **Given** таблица с задачами в порядке добавления, сортировка не выбрана, **When** пользователь кликает на заголовке "Название", **Then** задачи перестраиваются по названию по возрастанию, в заголовке отображается "Название ▲"
2. **Given** задачи отсортированы по "Название" по возрастанию ("Название ▲"), **When** пользователь снова кликает на заголовке "Название", **Then** задачи перестраиваются по убыванию, в заголовке отображается "Название ▼"
3. **Given** задачи отсортированы по "Название" по убыванию ("Название ▼"), **When** пользователь снова кликает на заголовке "Название", **Then** сортировка сбрасывается, задачи возвращаются в исходный порядок (порядок из файла), заголовок отображается как "Название" без стрелки
4. **Given** задачи отсортированы по "Название" по возрастанию, **When** пользователь кликает на заголовке "Статус", **Then** сортировка переключается на "Статус" по возрастанию, индикатор на "Название" исчезает, на "Статус" отображается "Статус ▲"

### User Story 2 - Сохранение сортировки при смене фильтров (Priority: P2)

При применении или сбросе фильтров (поиск, статус, тег) через кнопки "Применить" или "Сбросить" текущая сортировка сохраняется. Пользователь не теряет выбранный порядок сортировки при изменении фильтров.

**Why this priority**: Если сортировка сбрасывается при смене фильтра, пользователю приходится каждый раз заново настраивать порядок — это снижает продуктивность.

**Independent Test**: Отсортировать задачи по "Срок", применить фильтр по статусу "todo", проверить что сортировка по "Срок" сохранилась.

**Acceptance Scenarios**:

1. **Given** задачи отсортированы по "Срок" по возрастанию, **When** пользователь применяет фильтр (например, search="купить"), **Then** таблица обновляется с фильтром, сортировка по "Срок" по возрастанию сохраняется, заголовок "Срок ▲" остаётся
2. **Given** задачи отсортированы по "Название" по убыванию, **When** пользователь нажимает "Сбросить" (сброс фильтров), **Then** таблица обновляется без фильтров, сортировка по "Название" по убыванию сохраняется

### User Story 3 - Работа с пустым списком задач (Priority: P3)

Пользователь открывает TaskHub без задач. Заголовки колонок остаются кликабельными, приложение не выдаёт ошибок при клике на заголовок.

**Why this priority**: Граничное состояние — приложение должно корректно обрабатывать пустой список задач без падений.

**Independent Test**: Открыть приложение без задач, кликнуть на любой заголовок колонки, убедиться что приложение не выдаёт ошибку.

**Acceptance Scenarios**:

1. **Given** приложение без задач, **When** пользователь кликает на любой заголовок колонки, **Then** приложение не выдаёт ошибку, заголовок остаётся кликабельным, состояние сортировки устанавливается

## Edge Cases

- **Одна задача в списке**: Сортировка одной задачи не изменяет отображение, но индикатор появляется/переключается как обычно.
- **Все задачи имеют одинаковое значение в сортируемом поле**: Сортировка выполняется, порядок сохраняется исходный (стабильная сортировка на backend).
- **Быстрые повторные клики**: Пользователь быстро кликает на нескольких колонках подряд — в конце отображается состояние последней кликнутой колонки.
- **Клик на заголовке при отсутствии задач**: Сортировка переключается (состояние сохраняется), таблица остаётся пустой.
- **Ширина колонки при добавлении стрелки**: Добавление стрелки "▲" или "▼" в заголовок не вызывает перерасчёт ширины колонки и не обрезает текст заголовка.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Заголовки колонок таблицы задач должны быть кликабельными: при наведении курсор меняется на руку (hand2)
- **FR-002**: Клик по заголовку колонки запускает сортировку по соответствующему полю: "Название" → title, "Статус" → status, "Срок" → due_date, "Теги" → tags
- **FR-003**: При клике на колонку, которая не отсортирована, направление устанавливается "asc"
- **FR-004**: При клике на колонку, отсортированную "asc", направление переключается на "desc"
- **FR-005**: При клике на колонку, отсортированную "desc", сортировка сбрасывается (возвращается порядок из файла)
- **FR-006**: При клике на другую колонку индикатор предыдущей колонки сбрасывается, устанавливается новый
- **FR-007**: В заголовке отсортированной колонки отображается текстовая стрелка: "▲" для asc, "▼" для desc, после названия с пробелом
- **FR-008**: В заголовке неотсортированной колонки стрелка отсутствует
- **FR-009**: При изменении сортировки таблица обновляется (refresh) с новыми параметрами sort_by и sort_order
- **FR-010**: Состояние сортировки (колонка + направление) хранится в окне и сохраняется при смене фильтров
- **FR-011**: При нажатии "Применить" (фильтры) текущая сортировка сохраняется
- **FR-012**: При нажатии "Сбросить" (фильтры) текущая сортировка сохраняется
- **FR-013**: Сортировка не изменяет порядок задач в файле хранилища
- **FR-014**: CLI-контракты не изменяются
- **FR-015**: Не добавляются новые внешние зависимости
- **FR-016**: При пустом списке задач сортировка не вызывает ошибок, состояние сортировки сохраняется

## Key Entities *(include if feature involves data)*

- **SortState**: Состояние сортировки GUI — текущая колонка (title/status/due_date/tags/None) и направление (asc/desc/без сортировки)
- **Column**: Колонка таблицы — отображаемое название и соответствующее поле сортировки backend
- **Task**: Задача (существующая сущность TaskHub)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может отсортировать задачи по любой из четырёх колонок одним кликом
- **SC-002**: Пользователь всегда может определить текущую сортировку по индикатору в заголовке колонки без дополнительных действий
- **SC-003**: Циклическое переключение (asc → desc → без сортировки) работает для каждой из четырёх колонок
- **SC-004**: Сортировка сохраняется после применения и сброса фильтров в 100% случаев
- **SC-005**: Добавление стрелки в заголовок не изменяет ширину колонки и не обрезает текст

## Assumptions

- Циклическое переключение сортировки: asc → desc → без сортировки (3 состояния). Это стандартное поведение для десктопных таблиц (Excel, LibreOffice, большинство IDE).
- Стрелка отображается как текст в заголовке колонки (ttk.Treeview не поддерживает встроенные иконки в заголовках без замены виджета)
- Ширина колонки не пересчитывается при добавлении/удалении стрелки; текст заголовка обрезается многоточием при необходимости
- Состояние сортировки не сохраняется между сессиями приложения (при каждом запуске GUI сортировка сбрасывается на исходное состояние)
- Клик на заголовке — единственный способ изменить сортировку (нет контекстного меню, нет горячих клавиш для сортировки в v1)
- GUI делегирует сортировку backend (Storage.list_tasks), не выполняет сортировку самостоятельно
