# Research: Сортировка задач в GUI TaskHub

## Неизвестные параметры из Technical Context

Все параметры Technical Context определены на основе существующего кода и спецификации. Неизвестных параметров нет (все NEEDS CLARIFICATION разрешены в фазе уточнения спецификации).

## Исследование: поведение сортировки в десктопных таблицах

**Decision**: Циклическое переключение сортировки asc → desc → без сортировки (3 состояния) при повторном клике на ту же колонку.

**Rationale**: Стандартное поведение для десктопных таблиц (Excel, LibreOffice, большинство IDE). Указано в Assumptions спецификации и подтверждено уточнением.

**Alternatives considered**:
- Двухсостоятельное переключение asc → desc → asc (отклонено: не даёт способа вернуться к исходному порядку файла без смены колонки)
- Добавление отдельной кнопки "Сброс сортировки" (отклонено: избыточно, клик на активную колонку уже сбрасывает)

## Исследование: визуальный индикатор сортировки в ttk.Treeview

**Decision**: Стрелка направления сортировки отображается как текстовое наложение в заголовке колонки (например, "Название ▲").

**Rationale**: ttk.Treeview не поддерживает встроенные иконки в заголовках без замены виджета. Текстовое наложение — минимальное изменение, не требует новых зависимостей.

**Alternatives considered**:
- Замена ttk.Treeview на кастомный виджет с поддержкой иконок (отклонено: нарушает принцип V Local Simplicity, добавляет сложность)
- Использование отдельной метки рядом с таблицей (отклонено: пользователь не свяжет индикатор с конкретной колонкой)

## Исследование: интеграция с backend

**Decision**: GUI вызывает `controller.list_tasks(status, tag, search, sort_by, sort_order)` с параметрами:
- `sort_by` ∈ {"title", "status", "due_date", "tags", None}
- `sort_order` ∈ {"asc", "desc"}

**Rationale**: Соответствует контракту backend (001-tasks-sort-back). Состояние "без сортировки" в GUI маппится на `sort_by=None`, `sort_order="asc"`.

**Alternatives considered**:
- Выполнение сортировки на стороне GUI (отклонено: нарушает принцип II Shared Core, дублирует логику backend)
- Добавление отдельного метода контроллера для сортировки (отклонено: избыточно, list_tasks уже принимает sort_by/sort_order)

## Исследование: состояние сортировки между сессиями

**Decision**: Состояние сортировки не сохраняется между сессиями приложения. При каждом запуске GUI сортировка сбрасывается на исходное состояние.

**Rationale**: Подтверждено уточнением. Для локального Tkinter-приложения без сетевой синхронизации проще начать с чистого состояния.

**Alternatives considered**:
- Сохранение в конфигурационном файле (отклонено: добавляет сложность, не требуется по specifications)
- Сохранение в tasks.json (отклонено: нарушает стабильность данных, сортировка — только отображение)

## Исследование: обработка пустого списка задач

**Decision**: При пустом списке задач заголовки колонок остаются кликабельными, состояние сортировки устанавливается, приложение не выдаёт ошибок.

**Rationale**: Граничное состояние, указано в User Story 3 и FR-016.

**Alternatives considered**: Отключение заголовков при пустом списке (отклонено: ухудшает UX, пользователь не понимает почему колонки некликабельны)

## Исследование: ширина колонок при добавлении стрелки

**Decision**: Ширина колонки не пересчитывается при добавлении/удалении стрелки. Текст заголовка обрезается многоточием при необходимости.

**Rationale**: Минимальное изменение, не требует перерасчёта макета таблицы. Стрелка добавляется в существующий текст заголовка.

**Alternatives considered**: Автоматическое расширение колонки под стрелку (отклонено: требует пересчёта всех ширин, может ломать макет)
