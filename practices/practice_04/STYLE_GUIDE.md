# Google Python Style Guide (Project Adaptation)

- Контракт JSON-хранилища: tasks.json всегда имеет вид { "version": 1, "tasks": [...] }; элементы списка tasks — точная сериализация dataclass Task (через Task.to_dict) без дополнительных полей; запись в UTF-8 с indent=2 и ensure_ascii=false; изменение схемы допускается только с bump версии и сопутствующими правками валидаторов/CLI.

- Атомарная запись и история откатов: все изменения выполняются через save_tasks/_write — сначала snapshot текущего файла (pre-image), затем запись во временный файл и atomic replace (.tmp -> tasks.json); история хранится в .taskhub/history, поддерживаются только 3 последних snapshot'а, сбои истории не блокируют основную запись; undo работает только по истории, 1-3 шага, при нехватке истории выбрасывается ValueError("no history to undo").

- Контракт CLI-вывода и кодов выхода: формат list строго "<id> [status] title (due=... tags=...)" (при отсутствии due используется "-"); команда undo при успехе печатает ровно "undo: ok (N)"; ошибки пользовательского ввода и отсутствия сущностей завершаются ненулевым exit code через typer.Exit(code=1), stdout использовать только для заявленного вывода.

- Модель данных, идентификаторы и даты: Task — dataclass с полями id, title, status ("todo"|"done"), created_at (UTC), due_date (optional), tags (list); не использовать изменяемые значения по умолчанию, для коллекций применять default_factory; идентификаторы — UUID4 через Task.new; timestamps хранить в ISO UTC с суффиксом Z по константе ISO_FORMAT, due_date (если задана) в том же формате.

- Стиль кода и разделение ответственности: CLI (app.py) только парсит аргументы, оркестрирует вызовы и печатает вывод; файловая логика и история — в storage.py; модель и сериализация — в models.py; типизация обязательна (from __future__ import annotations, явные Optional/List в сигнатурах); именование snake_case, у CLI-команд краткие докстринги; соблюдать максимальную длину строки 100 символов (см. pyproject.toml) и не добавлять новые зависимости без согласования.
