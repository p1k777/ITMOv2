# Design

## Context

Мотивация описана в proposal.md. Контракт — в specs/task-search/spec.md.
Команда list в app.py передаёт фильтры в Storage.list_tasks; тот читает
JSON, создаёт Task и последовательно фильтрует список. get_storage и load
сохраняют существующую автоинициализацию отсутствующего файла.
MCP вызывает тот же метод с именованными status и tag.

Design включён для согласования изменений двух модулей, семантики Unicode
и обратной совместимости общего метода до реализации.

## Goals / Non-Goals

**Goals:** держать выборку в Storage, а разбор опций и печать в CLI;
сохранить совместимость старых вызовов без search.

**Non-Goals:** новый поисковый индекс, изменение сериализации,
расширение MCP-интерфейса, изменение правил инициализации и новая валидация хранилища.

## Decisions

1. Добавить `search: Optional[str] = None` последним параметром list_tasks.
   Полная сигнатура:

   ```python
   def list_tasks(
       self,
       status: Optional[str] = None,
       tag: Optional[str] = None,
       search: Optional[str] = None,
   ) -> List[Task]:
   ```

   Старые позиционные и именованные вызовы сохраняют прежнюю выборку.
   Фильтровать после status и tag: это сохраняет AND и исходный порядок.
   Альтернатива — фильтрация в CLI — дублировала бы ответственность Storage.
2. Использовать `casefold()` у запроса и названия и буквальное вхождение.
   Вычислить `search.casefold()` один раз. В отличие от lower это рассчитано
   на Unicode-сопоставление без регистра; регулярные выражения не нужны.
   Дополнительная Unicode-нормализация, транслитерация и приравнивание «ё» к «е»
   не добавляются. CLI и Storage используют одну семантику выбора задач.
3. None и пустая строка отключают поисковый фильтр.
   Пробелы не обрезаются, запрос из пробелов
   не приравнивается к пустому. Это буквальная подстрока без скрытой нормализации.
4. Новая строковая Typer-опция передаётся именованным аргументом в Storage.
   Отсутствующее значение обрабатывает существующий парсер CLI;
   отдельная валидация запроса не нужна.
5. Не вызывать методы записи при поиске. Существующий путь init/load
   остаётся прежним; запрет записи относится к уже существующим данным.
6. Поисковый контракт предполагает корректное хранилище с `title: str`.
   Существующий путь загрузки и обработка его ошибок сохраняются: не добавлять
   преобразование title через str(), пропуск повреждённых записей, новую валидацию
   или новый перехват ошибок. Поиск по некорректным типам полей вне контракта.

## Risks / Trade-offs

- Unicode casefold может расширять символы → явно использовать одну
  операцию для запроса и названия; проверить кириллицу, латиницу и совпадение
  Straße/STRASSE, отличающее casefold от lower.
- Визуально одинаковые строки могут иметь разное представление Unicode → проверить
  отсутствие канонической нормализации на полных последовательностях
  `"\u0439"` и `"\u0438\u0306"` в обоих направлениях.
- Незаметное изменение порядка/вывода → сравнивать полные строки CLI
  и относительный порядок нескольких совпадений.
- Непреднамеренная запись или snapshot → сравнивать байты файла,
  имена и содержимое истории до и после поиска в тестовом каталоге.
- Исторически слабые проверки undo → проверять поиск без новых записей,
  не включать исправление undo в эту фичу.

## Migration Plan

Миграция данных не нужна: меняются только необязательные параметры.
Откат — удаление новой опции и поискового фильтра; данные совместимы.
Проверки из practice_04: `.venv/bin/python -m pytest -q` и
`.venv/bin/python tools/lint.py`.
Исходное состояние ранее проверено: 20 passed и taskhub-lint: ok;
имеются предупреждения datetime.utcnow(), не связанные с поиском.
