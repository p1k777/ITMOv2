# Proposal

## Why

TaskHub умеет фильтровать задачи по статусу и тегу, но найти задачу по части
названия пока нельзя. Поиск в существующем списке позволит быстро находить
задачи без просмотра всего хранилища.

## What Changes

- Добавить `list --search "текст"`: поиск подстроки только в названии,
  через буквальное вхождение `search.casefold()` в `title.casefold()`, включая кириллицу.
- Объединять поиск с `--status` и `--tag` по AND.
- При отсутствии совпадений возвращать пустой вывод и код 0.
- Без поиска и при `--search ""` сохранять прежнюю выборку.
- Сохранять формат строк, порядок результатов, существующий файл данных
  и историю undo. Существующая автоинициализация отсутствующего файла сохраняется.
- Вне изменения: поиск по ID/тегам/датам, регулярные выражения, нечёткий поиск,
  сортировка, новые MCP-параметры, изменение JSON-схемы и исправление undo.
- Дополнительная Unicode-нормализация, транслитерация, приравнивание «ё» к «е»
  и новая валидация хранилища не входят в изменение.
- Поисковый контракт предполагает корректное хранилище со строковыми названиями;
  существующая обработка ошибок загрузки сохраняется.

## Capabilities

### New Capabilities

- `task-search`: поиск задач по подстроке названия в CLI и Storage,
  совместимый с существующими фильтрами списка.

### Modified Capabilities

Нет: основные спецификации OpenSpec пока отсутствуют.

## Impact

- `src/taskhub/app.py`: новая необязательная опция команды `list`.
- `src/taskhub/storage.py`: `list_tasks(status=None, tag=None, search=None)`;
  `search` добавляется последним необязательным параметром.
- `tests/`: unit- и CLI-проверки контракта и совместимости.
- Модель Task, JSON-формат и зависимости остаются прежними.
- Старые позиционные и именованные вызовы `Storage.list_tasks`, а также
  MCP-обёртки остаются совместимыми.
