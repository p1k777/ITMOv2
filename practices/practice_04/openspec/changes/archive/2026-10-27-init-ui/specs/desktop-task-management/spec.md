# Spec Delta

## Purpose

Предоставляет оконный доступ ко всем готовым возможностям локального TaskHub:
просмотру, поиску, фильтрам, добавлению, выполнению, редактированию, откату изменений
и проверке целостности, сохраняя совместимость с существующим хранилищем и CLI.

## ADDED Requirements

### Requirement: Standalone desktop launch

Система SHALL предоставлять запуск `python -m taskhub.gui` из окружения с установленным
TaskHub или настроенным PYTHONPATH. Окно SHALL работать с tasks.json в текущем рабочем
каталоге и показывать абсолютный путь к файлу. Отсутствующее хранилище SHALL
инициализироваться пустым в прежнем формате версии 1 без истории.

#### Scenario: Open existing storage
- **GIVEN** в рабочем каталоге есть корректный tasks.json
- **WHEN** пользователь запускает desktop UI
- **THEN** открывается одно окно TaskHub со списком задач и абсолютным путём файла
- **AND** загрузка не меняет байты файла и существующую историю

#### Scenario: First launch
- **GIVEN** tasks.json и история в рабочем каталоге отсутствуют
- **WHEN** пользователь запускает desktop UI
- **THEN** создаётся пустое хранилище версии 1 без snapshots истории
- **AND** окно показывает пустую таблицу и сообщение «Нет задач»

### Requirement: Task list and explicit refresh

Окно SHALL показывать выбранные активными фильтрами задачи в порядке хранения
в таблице с колонками «Название», «Статус», «Срок», «Теги» и вертикальной прокруткой.
Статусы SHALL отображаться как
todo/done, отсутствующий срок как «-», теги через запятую. Кнопка «Обновить» SHALL
перечитывать список; успешное обновление SHALL сбрасывать выбор строки.

#### Scenario: Existing task fields
- **GIVEN** есть задачи со сроком и без него, с несколькими тегами и разными статусами
- **WHEN** список успешно загружен без фильтров
- **THEN** таблица показывает значения этих полей в исходном порядке
- **AND** количество показанных задач указано в строке состояния

#### Scenario: Empty storage and empty selection
- **WHEN** успешно загружен пустой результат без фильтров
- **THEN** показано «Нет задач»
- **WHEN** успешно загружен пустой результат с активными фильтрами
- **THEN** показано «Ничего не найдено»

#### Scenario: External change
- **GIVEN** задачи изменены через CLI после открытия окна
- **WHEN** пользователь нажимает «Обновить»
- **THEN** таблица отражает актуальную выборку с прежними активными фильтрами
- **AND** чтение не меняет данные и историю
- **AND** ни одна строка не выбрана

### Requirement: Search and combined filters

Окно SHALL предоставлять поиск по названию, фильтр «Все / todo / done» и фильтр
точного тега. «Применить» SHALL объединять их по AND: поиск — буквальная подстрока
после casefold без trim/дополнительной нормализации, тег — точное совпадение.
Пустые поиск/тег и «Все» SHALL отключать соответствующие ограничения.

#### Scenario: Combined selection
- **GIVEN** задачи с разными статусами, названиями и тегами
- **WHEN** пользователь задаёт «ПРАК», todo, тег «учеба» и нажимает «Применить»
- **THEN** видны только todo с тегом «учеба» и подстрокой «прак» в названии без учёта регистра
- **AND** относительный порядок задач, файл и история не меняются

#### Scenario: Literal query
- **WHEN** пользователь применяет поиск « » или «[demo]»
- **THEN** пробел или скобки учитываются буквально, без регулярных выражений
- **AND** поиск по «STRASSE» находит «Straße», а «елка» не находит «ёлка»

#### Scenario: Reset and empty result
- **GIVEN** активные фильтры не находят совпадений
- **WHEN** пользователь видит пустую таблицу
- **THEN** показано «Ничего не найдено», а не ошибка загрузки
- **WHEN** пользователь нажимает «Сбросить»
- **THEN** поля фильтров очищены, статус установлен в «Все», показаны все задачи

#### Scenario: Unapplied filter input
- **GIVEN** пользователь изменил поля фильтров, но не нажал «Применить»
- **WHEN** выполняется refresh или перечитывание после записи
- **THEN** используются ранее применённые фильтры, а не черновые значения полей

### Requirement: Add task with optional fields

UI SHALL предоставлять форму добавления с названием, необязательными сроком и одним
тегом. Название SHALL обрезаться по краям; пустое название SHALL отклоняться.
Пустые срок/тег SHALL означать отсутствие срока/тегов. Новая задача SHALL иметь
уникальный ID и статус todo. При успешной записи форма SHALL закрываться,
список SHALL перечитываться с активными фильтрами.

#### Scenario: Successful add
- **WHEN** пользователь открывает добавление, вводит «  Сделать практику  »
  без срока/тега и сохраняет
- **THEN** сохраняется задача «Сделать практику» со статусом todo, без срока и тегов
- **AND** без активных фильтров после перечитывания задача видна в таблице, форма закрыта
- **AND** после перезапуска задача остаётся доступна

#### Scenario: Blank title
- **GIVEN** поле названия пусто либо содержит только пробельные символы
- **WHEN** пользователь сохраняет форму
- **THEN** окно показывает ошибку «Введите название задачи» и сохраняет введённый текст
- **AND** хранилище и история не изменяются

#### Scenario: Optional values and cancellation
- **WHEN** пользователь сохраняет задачу со сроком `2026-10-28T12:00:00.000000Z`
  и тегом «учеба»
- **THEN** сохраняются указанный срок и список тегов из одного значения «учеба»
- **WHEN** пользователь открывает новую форму и нажимает «Отмена»
- **THEN** задача не создаётся и история не меняется

### Requirement: Due date input format

В формах добавления и редактирования UI SHALL показывать подсказку формата срока
`YYYY-MM-DDTHH:MM:SS.ffffffZ` (UTC), сохранять корректное значение без преобразования
часового пояса и отклонять некорректное непустое значение до записи.
Существующие значения SHALL отображаться без автоматического исправления.

#### Scenario: Invalid due date
- **WHEN** пользователь сохраняет новый или изменяемый срок «завтра»
- **THEN** форма остаётся открытой с введёнными значениями и ошибкой формата
- **AND** файл и история не изменяются

### Requirement: Edit selected fields

UI SHALL позволять редактировать выбранную задачу по ID: название, срок и тег.
Каждое поле SHALL иметь явный выбор «Изменить»; остальные поля сохраняются.
Изменяемое название SHALL быть непустым после trim; срок SHALL быть непустым
и корректным. Изменяемый тег SHALL заменять весь список одним значением,
а пустой SHALL очищать список. ID и статус SHALL сохраняться.

#### Scenario: Preserve unselected fields
- **GIVEN** выбранная задача имеет срок и теги «учеба», «python»
- **WHEN** пользователь меняет только название и сохраняет
- **THEN** название изменено, срок, теги, ID, статус и created_at прежние
- **AND** форма закрывается, список перечитан с активными фильтрами

#### Scenario: Replace or clear tags
- **WHEN** пользователь отмечает изменение тега и задаёт «работа»
- **THEN** после сохранения список тегов равен [«работа»]
- **WHEN** пользователь снова редактирует задачу с изменением тега на пустой
- **THEN** после сохранения список тегов пуст

#### Scenario: No change and unsupported due removal
- **WHEN** пользователь сохраняет edit без отмеченных полей
- **THEN** запись не выполняется и показано «Выберите поля для изменения»
- **WHEN** пользователь отмечает изменение срока, оставив его пустым
- **THEN** форма сообщает, что очистка срока не поддерживается, без записи

#### Scenario: Cancel or missing task
- **WHEN** пользователь отменяет редактирование
- **THEN** файл и история не изменяются
- **WHEN** сохраняется изменение задачи, исчезнувшей из файла
- **THEN** показано «Задача не найдена. Обновите список», без успешной записи

### Requirement: Complete selected task

Окно SHALL позволять выбрать не более одной задачи. Кнопка «Выполнено» SHALL быть
доступна только для выбранной задачи todo из успешно загруженного списка.
Действие SHALL использовать ID выбранной задачи. При успехе список SHALL
перечитываться, статус SHALL стать done. Для исчезнувшей задачи SHALL отображаться
ошибка без сообщения об успехе.

#### Scenario: Complete one of equal titles
- **GIVEN** две задачи todo с одинаковыми названиями и разными ID
- **WHEN** пользователь выбирает вторую и нажимает «Выполнено»
- **THEN** только выбранная задача становится done и остаётся done после перезапуска
- **AND** после перечитывания выбор сброшен и кнопка недоступна

#### Scenario: Completed task leaves active selection
- **GIVEN** активен фильтр todo
- **WHEN** выбранная задача успешно отмечена выполненной
- **THEN** фильтр todo остаётся активным, задача исчезает из таблицы
- **AND** в хранилище задача существует со статусом done

#### Scenario: No actionable selection
- **WHEN** строка не выбрана либо выбрана задача done
- **THEN** кнопка «Выполнено» недоступна и запись не выполняется

#### Scenario: Task disappeared
- **GIVEN** выбранная задача удалена из хранилища внешним действием
- **WHEN** пользователь нажимает «Выполнено»
- **THEN** окно показывает «Задача не найдена. Обновите список»
- **AND** действие не изменяет хранилище и историю

### Requirement: Undo one to three changes

Окно SHALL предоставлять выбор числа шагов 1–3 (по умолчанию 1) и кнопку
«Отменить изменения». Undo SHALL откатывать общую историю файла, включая изменения
CLI, независимо от фильтров. После успеха список SHALL перечитываться с прежними
фильтрами. Нехватка истории SHALL давать видимую ошибку без сообщения об успехе.

#### Scenario: Undo edit with filters
- **GIVEN** задача была изменена, а список отфильтрован
- **WHEN** пользователь отменяет один шаг
- **THEN** задача восстановлена из последнего snapshot, фильтры сохранены
- **AND** показано количество отменённых изменений, выбор строки сброшен

#### Scenario: Multiple steps and insufficient history
- **GIVEN** есть три snapshots
- **WHEN** пользователь выбирает 3 и отменяет изменения
- **THEN** восстановлено состояние до этих трёх изменений
- **WHEN** пользователь снова пытается отменить при пустой истории
- **THEN** показана ошибка нехватки истории, данные и история не изменены

### Requirement: Read-only integrity check

Кнопка «Проверить данные» SHALL проверять весь файл независимо от фильтров,
не изменяя его и историю, и оставаться доступной при ошибке загрузки таблицы.
UI SHALL показывать результат, доступные счётчики total/todo/done и все найденные
проблемы. Ошибки чтения/JSON SHALL отображаться как ошибки проверки, без исправления
или создания файла.

#### Scenario: Successful validation
- **WHEN** пользователь проверяет корректный файл при активном фильтре todo
- **THEN** показан успешный результат и счётчики всего файла, включая done
- **AND** байты файла и snapshots не изменились

#### Scenario: Issues and unreadable data
- **GIVEN** файл содержит неподдерживаемую версию и tasks в виде строки вместо списка,
  а таблица уже показала ошибку чтения
- **WHEN** пользователь нажимает «Проверить данные»
- **THEN** проверка доступна и показывает проблему версии
- **WHEN** файл содержит некорректный JSON либо отсутствует
- **THEN** показана ошибка проверки без записи/создания файла

### Requirement: Recoverable operation errors

Ошибки чтения, разбора данных и записи SHALL отображаться в окне, не выдавая их
за пустой список или успех. При ошибке чтения прежние строки SHALL очищаться,
изменяющие действия SHALL отключаться, а «Обновить» и «Проверить данные» SHALL
оставаться доступными. При ошибке записи формы до подтверждённого успеха
введённые значения SHALL сохраняться.

#### Scenario: Invalid file then recovery
- **GIVEN** tasks.json содержит некорректный JSON
- **WHEN** окно загружает список
- **THEN** показана ошибка чтения, а не «Нет задач», файл не заменяется пустым
- **AND** после внешнего исправления и нажатия «Обновить» список снова доступен

#### Scenario: Failed write
- **GIVEN** операция записи завершается ошибкой
- **WHEN** пользователь добавляет, редактирует, выполняет задачу или вызывает undo
- **THEN** показана ошибка операции и не показано подтверждение успеха
- **AND** UI не показывает неподтверждённое изменение как сохранённое

#### Scenario: Write succeeded but reload failed
- **GIVEN** запись добавленной задачи успешна, но последующее чтение завершилось ошибкой
- **WHEN** UI обрабатывает результат
- **THEN** форма уже закрыта и показано, что запись успешна, но список не удалось обновить
- **AND** изменяющие действия недоступны до успешного «Обновить»

### Requirement: Shared persistence and CLI compatibility

Desktop UI SHALL использовать существующие формат данных и механизм записи/истории
TaskHub. Успешные операции add/done/edit SHALL использовать pre-image через прежний
механизм истории. CLI и его вывод SHALL сохранять прежнее поведение; запуск CLI
SHALL оставаться возможным без установленного Tcl/Tk.

#### Scenario: Desktop write is visible and undoable from CLI
- **GIVEN** UI добавил задачу в существующее корректное хранилище
- **WHEN** CLI list и затем CLI undo вызываются в том же рабочем каталоге
- **THEN** list видит новую задачу в прежнем формате, undo отменяет добавление
- **AND** «Обновить» в окне отражает откат

#### Scenario: CLI without Tk
- **GIVEN** Python поддерживает зависимости CLI, но не имеет Tcl/Tk
- **WHEN** пользователь выполняет существующие CLI-команды
- **THEN** они работают без импорта GUI и сохраняют прежний контракт
