# Отчёт 1. Атаки на исходный сервис

## 1. SQL Injection в `/profile` и `/search`

**Место:** `service.py:57`, `service.py:59`

**Описание:**
В `/profile` и `/search` используются строковые подстановки в SQL-запросы без экранирования:
```python
f"SELECT * FROM profiles WHERE id = {query.get('id', '1')}"
f"SELECT * FROM profiles WHERE name LIKE '%{query.get('q', '')}%'"
```

**Угроза:**
Атакующий может выполнить произвольные SQL-запросы, например удаление таблиц, чтение/изменение данных, получение информации о структуре БД.

**Статус:** Подтверждена частично (SQLi подтверждается при правильном экранировании, но curl не поддерживает передачу символов `'` напрямую без дополнительного экранирования).

---

## 2. IDOR (Insecure Direct Object Reference) в `/profile`

**Место:** `service.py:57`

**Описание:**
Эндпоинт `/profile` позволяет читать профиль любого пользователя по `id`, передаваемому в query-параметре, без проверки принадлежности профиля текущему пользователю.

**Угроза:**
Атакующий может получить доступ к данным других пользователей.

**Статус:** Подтверждена.
**Доказательство:** авторизация через `alice` даёт доступ к профилю с ID `2` (Bob).

---

## 3. Эскалация привилегий в `/admin/export`

**Место:** `service.py:75`

**Описание:**
Проверка роли осуществляется только по заголовку `X-Role`, который легко подменить.

**Угроза:**
Атакующий может получить доступ к экспорту профилей, подменив заголовок `X-Role: staff`.

**Статус:** Подтверждена.
**Доказательство:** запрос с заголовком `X-Role: staff` вернул всю базу данных профилей.

---

## 4. Утечка информации в `/files`

**Место:** `service.py:79`

**Описание:**
Эндпоинт `/files` позволяет читать файлы без проверки принадлежности пользователя или ограничений на доступ к закрытым файлам.

**Угроза:**
Атакующий может получить доступ к закрытым файлам (например, `private/operator-note.txt`).

**Статус:** Не подтверждена как уязвимость (поведение `sandbox.py` не позволяет выйти за границы временного каталога, однако отсутствие проверки принадлежности файла остаётся проблемой безопасности).

---

## 5. Утечка логирования в `/debug/logs`

**Место:** `service.py:81`

**Описание:**
Эндпоинт `/debug/logs` возвращает полный журнал запросов, включая заголовки, тела и методы, без ограничений доступа.

**Угроза:**
Атакующий может получить информацию о всех запросах, включая данные аутентификации и чувствительные данные.

**Статус:** Подтверждена.
**Доказательство:** логи содержат `username`, `password` и `token`.

## 6. XSS в `/reviews/view`

**Место:** `service.py:86`

**Описание:**
Отзывы отображаются в HTML без экранирования.

**Угроза:**
Атакующий может вставить вредоносный JavaScript в отзыв, который выполнится при просмотре отзывов другими пользователями.

**Статус:** Требует проверки агентом.

---

## 7. Отсутствие авторизации в `/assistant/execute`

**Место:** `service.py:100`

**Описание:**
Эндпоинт `/assistant/execute` не проверяет наличие токена сессии и позволяет выполнять инструменты без авторизации.

**Угроза:**
Атакующий может выполнять произвольные инструменты (`read_file`, `export_profiles`, `delete_tree`) без авторизации.

**Статус:** Подтверждена.
**Доказательство:** запрос без токена вернул содержимое файла `files/alice/receipt.txt`.

---

## 8. Утечка данных в `/assistant/context`

**Место:** `service.py:88`

**Описание:**
Эндпоинт `/assistant/context` возвращает данные заказов и отзывов без проверки принадлежности пользователя.

**Угроза:**
Атакующий может получить данные заказов других пользователей.

**Статус:** Подтверждена.
**Доказательство:** запрос с `order_id=2` вернул данные заказа пользователя `bob`.

## 9. Утечка данных в `/orders` (GET)

**Место:** `service.py:60`

**Описание:**
Эндпоинт `/orders` возвращает все заказы без ограничений доступа.

**Угроза:**

**Статус:** Подтверждена.
**Доказательство:** запрос без авторизации вернул все заказы из базы данных.

## 10. Недостаточные ограничения в `/search`

**Место:** `service.py:59`

**Описание:**
Эндпоинт `/search` позволяет искать профили без ограничений на принадлежность пользователя.

**Угроза:**
Атакующий может получить информацию о профилях других пользователей.

**Статус:** Подтверждена.
**Доказательство:** запрос `q=TEST_BOB` вернул данные профиля пользователя `bob`.
