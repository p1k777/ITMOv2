## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед внешним LLM из diff удаляются токены, пароли и приватные ключи
- API-1: diff > 20 000 символов — HTTP 413
- REL-1: LLM-вызов с таймаутом 10 секунд; ошибки — контролируемый ответ
- OUT-1: ответ содержит summary, массив risks (≤3: file, line, evidence, risk), массив checks
- SCOPE-1: сервис только советует, не пишет код и не действует в GitHub
- QA-1: риски включаются только если подтверждены diff или правилом
- OBS-1: логировать только request_id, длительность и статус; не логировать diff и ответы модели

### Формат входа и результата

- Вход: строка `diff`
- Результат: JSON с `summary`, `risks[]` (<=3, элементы: file, line, evidence, risk), `checks[]`

### Ограничения и запрещённые действия

- Не отправлять секреты во внешний LLM (редакция обязательна)
- Отклонять слишком длинные diff (HTTP 413)
- Ограничивать длительность внешнего вызова 10 сек и нормализовать ошибки
- Не выполнять действия в репозитории; только рекомендации
- Не логировать содержимое diff и ответа модели

### Хороший пример

app/review_service.py:… — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED].

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Формальный перечень паттернов секретов и масок
- Детали SLA провайдера LLM
- Требуемая схема логирования в проде
